Deterministic, auditable guardrail between employees and internal AI tools. This page talks directly to the live FastAPI backend — zero build step, no bundler.

2 Request

📎

Text-only sends go to POST /guardrail/evaluate. With an image attached the send goes to POST /guardrail/evaluate-image (multipart: image file + conversation_id form field — that endpoint accepts no prompt text, so a typed caption is not transmitted with the file; remove the attachment to send it as text). Same Bearer session and the same editable conversation_id either way, so text and images share one conversation/trajectory history. Default OCR is offline/mock — it extracts no text, so uploads evaluate as an empty document and return ALLOW / LOW-001 by design. Set OPTICAL_OCR_PROVIDER=tesseract for real OCR (requires local Tesseract); only then does on-image text drive the decision.

How to read this: the badge is the policy decision. Green = ALLOW (no meaningful risk), yellow = REWRITE (safe reformulation before any LLM call), amber = CLARIFY, orange = REVIEW (human review required), red = BLOCK (never processed). Only ALLOW (or post-REWRITE) reaches the LLM gateway.

  
The role comes from the verified JWT — it is never a request body field. policies/policy.yaml (v0.2.0) currently applies the same rules to every role; the correct role plumbing is in place for when rules become role-aware.

  
Every evaluation produces an AuditEvent in the server-side SQLite audit log, regardless of outcome.
